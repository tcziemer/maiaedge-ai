# MaiaEdge AI Toolkit — Folder Map

This folder contains both the **AI toolkit codebase** (skills, context, plugins, enterprise project bundles) and the **working files** that the team uses day-to-day (deal docs, comp plans, samples, brand assets).

If you are a Claude agent loaded into this folder, read this file first to know where to look.

## Top-level layout

| Path | What it is | When to touch it |
|------|------------|------------------|
| `CLAUDE.md` | Toolkit reference: skills inventory, context categories, build instructions, team roster, key rules | Read before any task. Update only when you change toolkit structure. |
| `SETUP.md` | One-time setup instructions for a new contributor | Read once. |
| `CHEATSHEET.md` | Quick-reference card for sales reps | Read when doing rep-facing work. |
| `CHANGELOG.md` | Toolkit change history | Append when you ship a meaningful toolkit change. |
| `build.sh` | Assembles plugins and enterprise upload bundles from `skills/` + `context/` | Run after editing skills or context. Don't edit unless adding a new enterprise project or skill rename. |
| `maiaedge-rep-guide.html` | Standalone HTML guide for sales reps | Reference doc; don't edit casually. |
| `skills/` | **Toolkit** — skill definitions (one folder per skill, with `SKILL.md`) | Edit to add or change skill behavior. See CLAUDE.md "Creating a New Skill". |
| `context/` | **Toolkit** — knowledge base referenced by skills | Edit to update messaging, schemas, ICP, segment language, etc. |
| `plugins/` | **Toolkit** — Cowork plugin manifests (skill + context bundles) | Edit when packaging skills for Cowork. |
| `enterprise/` | **Toolkit** — Pre-assembled file bundles for Claude.ai enterprise Projects | Generated by `build.sh`. Don't hand-edit `upload/` contents. |
| `builds/` | **Toolkit** — generated zips and staged plugin folders | Gitignored. Output of `build.sh`. |
| `Nexus/` | Active customer engagement (Hubbard Campus). Design docs, emails, basis-of-design PDFs | Update as the engagement progresses. |
| `Quotes/` | Active customer quotes and order forms (DeepInfra, IENTC) | Update as new quotes go out. |
| `working-files/` | Everything else — comp plans, brand assets, outreach samples, pricing, metrics, strategic projects | See `working-files/README.md`. |

## Two mental models for AI agents

**If you are running a skill** (e.g., `cold-email`, `account-brief`, `call-prep`):
- Read the skill: `skills/<name>/SKILL.md`
- Read its referenced context files in `context/`
- Do not load `working-files/` unless the user explicitly points you there.

**If you are doing operational work** for a specific deal, person, or project:
- Active deals: look in `Nexus/` or `Quotes/`
- Sample outreach, comp plans, brand assets, prior intro briefings: `working-files/`
- Strategic projects (LMaaS, Neocloud): `working-files/strategic/`

## Boundary rule

`build.sh` only reads from `skills/`, `context/`, `plugins/` and writes to `builds/` + `enterprise/`. Anything outside those paths is safe to add, rename, or remove without breaking the build pipeline.
