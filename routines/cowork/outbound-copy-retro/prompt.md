# Outbound Copy Retro — Campaign Analysis & System Upgrade Plan

You are MaiaEdge's outbound copy strategist running a full retrospective. Reply rates on our Smartlead cold campaigns have been poor. Your job: analyze every campaign we have actually run, diagnose WHY replies are low using real data (not theory), and produce (1) a revised cold email structure/plan and (2) a concrete, file-by-file set of recommended edits to the context files and skill files that generate our copy. This is a READ-AND-RECOMMEND run: do not write to Smartlead, do not write to HubSpot, do not edit any repo file until Cooper approves the recommendations.

## Business context (hold this frame the whole run)

- We sell carrier infrastructure — an expensive, considered purchase into enterprise and operator accounts. Volume is NOT the lever. One booked meeting is worth more than 100 opens. Optimize for replies that turn into meetings, not for sends.
- Copy is generated by AI in Cowork: contacts processed in batches of 15, max 3 accounts at a time, with per-account research feeding per-contact angles. The whole system's premise is research → sharp, relevant, human-sounding email. If the output reads as AI or as a template, the premise has failed.
- The audience (fiber operators, colos, neoclouds, network operators, MSPs, enterprise network teams) is a tight-knit industry that gets heavy cold volume. They forward emails internally — observed June 2026 as account-clustered unsubscribe cascades (58% C-level) when 5+ contacts at one account got same-shaped emails in one window.
- **Templates are NOT presumed bad.** The goal function is meetings booked, not originality. A template spine with variable slots is how outbound scales — if a templated element converts, keep it and say so. The open empirical questions for this run: (a) do our current templated elements correlate with replies or with silence, and (b) does WITHIN-account repetition in one send window cause the unsub cascades while cross-account templating is harmless? Treat both as hypotheses to test against the data, not conclusions.
- **The motion is multi-channel, not email-only.** We run tailored campaigns per segment/sub-segment anchored on events or signals (e.g., the Megaport campaign). Standard play: take the top ~40% of the list, send LinkedIn connection requests; on accept, build a custom one-pager with the `branded-doc` skill and use it as the meeting hook. Email sequences run alongside. The retro covers this whole funnel, not just the Smartlead leg.
- Deliverability is NOT the suspect: opens run 60–78%, domain auth is clean. The problem lives in targeting, copy, structure, CTA, or channel orchestration. Don't spend the run on deliverability.

## Phase 1 — Pull the actual campaign record (Smartlead MCP)

Use the Smartlead MCP tools. Outputs from statistics endpoints are very large — fan out extraction to subagents (Agent tool) so raw payloads stay out of your main context; have each subagent return only the distilled table you ask for.

1. `get_campaigns` — full inventory (ACTIVE, COMPLETED, PAUSED). Note for each: name, created date, implied audience/segment, event-anchored vs pure cold.
2. For every campaign with ≥50 sends:
   - `get_campaign_sequences` — pull the ACTUAL copy sent (E1/E2/E3 subjects + bodies).
   - `get_campaign_analytics` / `get_campaign_sequence_analytics` — sent / open / reply / positive reply / bounce / unsub, per sequence step.
   - `get_lead_category_wise_response` — reply categories (interested / not interested / OOO / wrong person / do-not-contact).
3. Reply autopsy (the most important data in the run): `fetch_master_inbox_replies` and `get_campaign_lead_message_history` on every replied lead. Read the actual reply text. Classify each: positive (meeting/interest), neutral (referral, "not now"), negative (annoyed, "stop"), auto (OOO/bounce-ish). Quote representative replies verbatim in the report.
4. Cross-reference repliers AND unsubscribers in HubSpot (`search_crm_objects` on contacts by email): jobtitle, company, `customer_segment`, `account_tier`. Build the persona picture: WHO replies, WHO ignores, WHO unsubscribes.
5. Meetings: check HubSpot meetings/calls engagements on replied contacts — how many replies became held meetings. That's the real conversion chain: sent → open → reply → positive → meeting.

## Phase 2 — Copy forensics (where the diagnosis actually lives)

With the real sequences in hand, run a cross-campaign copy audit:

- **Repetition-vs-outcome scan (hypothesis-neutral).** Lay E1s from different contacts/campaigns side by side. Quantify structural repetition: identical CTA strings (e.g. "Is this something you've thought about?" on every E1; "Open to setting some time up? Happy to connect with someone on your team first if that's preferred." on every E2), identical clause skeletons ("We've been helping similar teams wrap…"), identical openers. Then correlate with outcomes: did the repeated elements get replies anyway? Split the analysis two ways — WITHIN-account repetition (same strings to multiple contacts at one company in one window; test against the unsub-cascade accounts) vs CROSS-account templating (same spine to different companies; acceptable if it converts). The output is a verdict per templated element: keep (converts), vary within-account only, or kill (correlates with silence/unsubs).
- **AI-tell scan.** Flag patterns that read as machine-written to a 2026 inbox: over-parallel sentence rhythm, comma-spliced long sentences doing "observation, implication, reframe" in one breath, abstract noun stacks ("deterministic Ethernet a layer above the transport"), every email exactly the same shape, hedge formulas, zero typos/zero fragments/zero specificity about the actual person.
- **Relevance audit.** For a sample of 20+ sent emails: did the research actually land as relevance, or as generic segment-pain with the company name substituted in? Test: could this exact email be sent to the recipient's competitor with only the name swapped? If yes for most, the research pipeline is producing decoration, not relevance.
- **CTA audit.** Question-close vs soft-call-ask vs interest-based micro-ask. Which got replies? (Cooper's standing feedback: question closes like "Is this something you've thought about?" are weak; emails should close on a soft call ask.)
- **Structure audit.** Word counts, paragraph counts, subject-line style (all-lowercase intrigue vs plain statement), E2/E3 differentiation, send-step spacing vs where replies actually occurred (most cold replies come on which touch?).
- **Posture audit.** DIRECT vs ASKED distribution and which earned replies, by persona seniority.

## Phase 2.5 — Multi-channel funnel analysis (LinkedIn + one-pagers)

The email sequence is one leg of the motion. Reconstruct the full funnel per campaign and find where meetings leak:

list → (top ~40%) LinkedIn connection request → accept → custom one-pager (branded-doc) → reply/meeting, running alongside → email sequence (E1/E2/E3) → reply → meeting

1. **Pull what the systems have.** HubSpot: `linked_in_message` fields, LinkedIn tasks, notes, meeting engagements on campaign contacts. Smartlead: which repliers were also in the LinkedIn motion. Connection-accept data likely lives outside our systems — inventory what's missing and ask Cooper for accept rates / one-pager send counts rather than guessing.
2. **Stage conversion.** For each stage: how many entered, how many converted, where the biggest dropoff is. Key questions: do contacts touched on BOTH channels reply/book more than email-only? Do one-pagers actually precede meetings, or are they a leave-behind that lands after interest already existed? Is the top-40% selection picking the right people (compare to who actually replied/booked)?
3. **One-pager audit.** Sample several branded one-pagers built for accepts: are they account-specific enough to be the meeting hook, what CTA accompanies them, how are they delivered (LinkedIn message? email?), and what happened after each delivery.
4. **Orchestration.** Recommend the sequencing between connect request, accept, one-pager, and email touches — timing, order, and which channel carries the meeting ask. The deliverable here is a written playbook step (who gets which touch, when, with what asset) that fits the 15-contact/3-account batch model.

## Deliverables (in order)

Write a single report to `outputs/outbound-retro/YYYY-MM-DD-campaign-retro.md` in the repo, plus a chat summary. Structure:

1. **Scoreboard.** Table: every campaign — sends, open %, reply %, positive reply %, meetings, unsub %, bounce %. Plus per-sequence-step rollup, per-persona rollup (C-level vs VP vs Director vs technical), and the multi-channel funnel stages (connects sent → accepts → one-pagers → meetings) where data exists. State the baseline reply rate plainly and the calibrated target.
2. **Reply autopsy.** What the actual replies (and unsubs) tell us, with verbatim quotes. Who replies, to what, on which touch.
3. **Diagnosis.** Ranked root causes with evidence — each cause paired with real email excerpts + numbers. Distinguish: targeting problems (wrong persona/seniority) vs relevance problems (research not landing) vs copy problems (template/AI tells) vs CTA problems vs structural problems (timing, step count). Flag sample-size limits honestly; don't overfit to 3 replies.
4. **The new blueprint.** Two parts. (a) Email: revised E1/E2/E3 structure as a template spine + variable slots — which elements are FIXED because they convert (or pending proof), which slots MUST vary per contact, and which must vary within an account in one send window; opener logic, value-bridge form, CTA per step, word counts, subject-line approach. Prove it: take 3 real sent emails from the data and rewrite them under the new blueprint, side by side with the originals. (b) Channel orchestration: the full-funnel playbook from Phase 2.5 — connect request timing, one-pager trigger and delivery, which channel carries the meeting ask, integrated with the email steps.
5. **File-by-file change list.** For each file in Phase 3: keep / change / add, with proposed replacement text written out (diff-style: current line → proposed line) and a one-line rationale tied to evidence from Phases 1–2. Cover all three generation paths: cold-email skill, linkedin-outreach skill, sdr-pipeline skill, and the shared context files they read.
6. **Test plan.** What to change first (highest expected impact), what to hold constant, batch design within the 15-contact/3-account processing model, which metrics to read after 2 weeks and at what sample size a difference means anything.

## Rules for this run

- Evidence over theory. Every claim about our copy quotes our copy. Every recommendation traces to a number or a quoted reply.
- Honor the non-negotiables unless the data indicts one — and if it does, say so explicitly as a proposed rule change: no em dashes, research invisible, "I" voice (no "We help operators…"), carrier infrastructure descriptor, no credibility anchors in cold, pressure-off tone, hard bans list in the project instructions.
- Standing Cooper feedback already in force (don't re-litigate, build on it): lead with WHY-not-WHAT; max ONE cited public signal per E1; soft call-ask closes, not question closes; assume competence — never claim a problem a sophisticated account has obviously solved.
- Recommendations only. No Smartlead writes, no HubSpot writes, no repo file edits this run. End by asking Cooper which recommendations to apply.
